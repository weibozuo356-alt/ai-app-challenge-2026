## 二、BugMentor 当前的数据链路

```text
用户在 React 页面填写调试信息
        ↓
前端通过 HTTP POST 发送 JSON
        ↓
FastAPI 的 /api/debug 接收请求
        ↓
Pydantic 检查输入类型、长度和提示等级
        ↓
main.py 调用 generate_debug_hint()
        ↓
ai_service.py 组织系统提示词和用户调试数据
        ↓
OpenAI Python SDK 向 DeepSeek API 发送 HTTPS 请求
        ↓
DeepSeek 根据提示等级生成个性化提示
        ↓
FastAPI 将提示作为 JSON 返回
        ↓
React 更新状态并把提示显示在页面中
```

昨天的数据链路是：

```text
React → FastAPI → 固定提示 → React
```

今天升级为：

```text
React → FastAPI → DeepSeek → 个性化提示 → React
```

## 三、API 密钥与环境变量

API 密钥相当于调用 DeepSeek 服务时使用的账号凭证。后端通过它证明自己有权使用模型服务。

密钥不能直接写在 Python 源代码里，否则代码上传到 GitHub 后，其他人可能盗用密钥并消耗账户额度。

因此项目使用 `backend/.env` 保存：

```text
DEEPSEEK_API_KEY
DEEPSEEK_BASE_URL
DEEPSEEK_MODEL
```

`python-dotenv` 负责读取 `.env`，`os.getenv()` 负责从环境变量中取得指定配置。

它们的关系是：

```text
.env：保存本地私密配置
        ↓
python-dotenv：加载配置
        ↓
os.getenv()：按名称读取配置
        ↓
OpenAI 客户端：使用配置连接 DeepSeek
```

`.gitignore` 会忽略 `.env`，因此真实密钥不会随代码提交到 GitHub。

## 四、OpenAI SDK 为什么可以调用 DeepSeek

今天安装了 `openai==3.0.0`，但实际调用的是 DeepSeek。

OpenAI SDK 在这里可以理解为一个通用的模型接口客户端。DeepSeek 提供了兼容这种调用格式的 API，因此只要设置：

- DeepSeek 的 API 密钥
- DeepSeek 的基础地址
- DeepSeek 的模型名称

同一套客户端就可以把请求发送给 DeepSeek，而不是发送给 OpenAI。

```text
Python 程序
    ↓
OpenAI SDK：负责整理和发送请求
    ↓
base_url 指定目标服务器
    ↓
DeepSeek API
```

SDK 是通信工具，`base_url` 才决定请求发送给哪个服务。

## 五、ai_service.py 的职责

今天没有把所有代码继续堆进 `main.py`，而是创建了独立的 `ai_service.py`。

`main.py` 负责：

- 创建 FastAPI 应用
- 接收 HTTP 请求
- 使用 Pydantic 校验数据
- 调用 AI 服务
- 返回 HTTP 响应

`ai_service.py` 负责：

- 加载模型配置
- 创建 DeepSeek 客户端
- 编写系统提示词
- 整理用户调试数据
- 调用模型
- 返回模型生成的提示

这种把不同职责拆到不同文件中的做法叫作关注点分离。

```text
main.py：Web 接口层
ai_service.py：AI 服务层
.env：配置与密钥
```

这样以后更换模型或修改提示词时，主要修改 `ai_service.py`，不会干扰 FastAPI 接口结构。

## 六、系统提示词与用户数据

系统提示词用来规定模型的身份、目标和行为，例如：

- 它是面向 Python 初学者的调试教练
- 目标是引导用户，而不是立即给答案
- 第1～5级分别允许透露多少信息
- 不执行用户代码
- 不声称运行过代码
- 输出简洁的中文提示

用户消息则包含：

- Python 代码
- 预期结果
- 报错信息
- 当前提示等级

它们的关系是：

```text
System Prompt：规定模型应该怎样工作
User Data：告诉模型这次需要分析什么
```

## 七、提示词迭代

第一次接入模型后，功能虽然能够运行，但输出出现了两个问题：

1. 模型使用了反引号和双星号等 Markdown 标记，页面按普通文字显示后不够美观。
2. 第二级提示直接给出了正确索引，过早泄露了答案。

因此继续修改系统提示词，加入：

- 不使用 Markdown
- 不复述任务
- 限制提示长度
- 第1级只观察现象
- 第2级只能缩小范围
- 第3级讲解概念并提问
- 第4级可以明确修改方向
- 第5级才能公布完整答案

这个过程叫作提示词迭代：先观察模型的真实输出，再根据产品目标调整规则并重新测试。

我还理解了：

> AI 给出了正确答案，不代表 AI 正确完成了产品任务。

普通代码助手追求快速给出答案；BugMentor 的核心价值是控制答案揭示的节奏，帮助用户形成调试思路。

## 八、请求超时与输出限制

创建客户端时设置了：

```python
timeout=30.0
```

它表示如果 DeepSeek 30秒内没有完成响应，程序就停止等待，避免后端接口一直卡住。

模型调用中设置了：

```python
max_tokens=500
```

它用于限制模型回复的最大长度，减少超长回复、等待时间和调用成本。

这两个设置都属于资源边界：

```text
timeout：限制等待时间
max_tokens：限制输出规模
```

## 九、异常处理

模型调用可能因为以下原因失败：

- 网络中断
- API 密钥失效
- 账户额度不足
- DeepSeek 服务繁忙
- 请求超时
- 模型没有返回有效内容

`main.py` 使用 `try/except` 捕获这些异常，并统一向前端返回：

```text
AI 教练暂时无法响应，请稍后再试。
```

这样用户不会看到服务器路径、内部异常或其他敏感信息。

异常处理的逻辑是：

```text
try：尝试调用 AI
        ↓
成功：返回 AI 提示
        ↓
失败：except 捕获异常
        ↓
返回安全、简洁的错误信息
```

## 十、安全边界

今天接入了外部 AI 服务，因此需要同时保护三类内容：

### 1. API 密钥

密钥只保存在 `.env` 中，不写进代码、不打印到终端、不提交 GitHub。

### 2. 用户代码

用户粘贴的代码只作为文本交给模型分析，BugMentor 不会在后端直接运行这些代码。

这避免了恶意代码访问文件、执行命令或破坏服务器。

### 3. 模型输出

模型返回的内容也不能被完全信任。当前前端只通过 React 把它作为普通文字显示，不使用 `eval()`，不把它作为系统命令执行，也不直接插入 HTML。

完整安全边界是：

```text
用户代码：不信任，只作为文本
API 密钥：严格保密，不进入提示词和 Git
模型输出：不信任，只作为文字展示
```

## 十二、今天遇到的问题和解决方法

### 1. 不确定模型是否真正连接成功

先创建独立的最小连接测试，只发送一句不包含项目代码的测试消息。

终端返回：

```text
MODEL_CONNECTION_OK
BugMentor 模型连接成功
```

证明 `.env`、API 密钥、模型名称和网络调用都正常。

### 2. 模型输出 Markdown 标记

在系统提示词中增加纯文本格式要求，禁止星号、反引号、标题和列表符号。

### 3. 第二级提示提前公布答案

进一步细化分级保密规则，明确第1～4级禁止透露哪些信息，只有第5级才能公布完整答案。

### 4. Git 提示当前目录不是仓库

执行 `cd ..` 后进入了 `D:\debugmentor`，而 `.git` 位于 `ai-app-challenge-2026` 中。

重新进入项目目录后，`git status` 恢复正常。

这让我理解：Git 命令需要在仓库目录或它的子目录中执行。

## 十四、多类型提示测试

完成列表索引案例后，我继续测试了第4级提示以及三种不同问题：

1. `SyntaxError`：例如 `for` 语句末尾缺少冒号。
2. `TypeError`：例如字符串与整数直接相加。
3. 逻辑错误：程序不报错，但计算平均值时使用了错误的除数。

第4级能够明确指出需要修改的区域，但没有直接贴出完整答案。其他案例也能根据代码、报错和预期结果生成对应提示。这说明功能测试不能只证明一个示例成功，还要选择不同类型和边界，判断能力是否具有普遍性。

## 十五、区分网络错误与 AI 服务错误

此前前端只要请求失败，就统一显示“连接后端失败”。但实际存在两种情况：

```text
FastAPI 没有运行
→ 浏览器无法建立连接
→ 提示“无法连接后端”

FastAPI 正常，但 DeepSeek 超时或不可用
→ 后端返回 HTTP 503
→ 提示“AI 教练暂时无法响应”
```

`503 Service Unavailable` 表示服务器暂时不能完成处理。前端现在会读取后端返回的安全 `detail`；只有网络完全无法连接、`fetch` 抛出 `TypeError` 时，才显示无法连接后端。

## 十六、自动化测试、断言与回归测试

手动测试需要打开网页、输入内容、点击按钮并观察结果。自动化测试则由程序自动完成输入、调用和结果判断。

今天创建了 `backend/test_main.py`，并通过5项测试：

1. `GET /` 返回状态码200和正确消息。
2. `/api/debug` 在模型成功时返回正确提示数据。
3. AI 服务故障时返回503，并且不泄露内部异常。
4. 空代码被 Pydantic 拒绝，返回422。
5. 超出1～5范围的提示等级被拒绝，返回422。

`TestClient` 可以在 Python 内部模拟客户端访问 FastAPI。断言（Assertion）表示“这个预期必须成立”，例如：

```python
self.assertEqual(response.status_code, 200)
```

以后每次修改后端后重新运行这些测试，就能快速发现旧功能是否被意外破坏。这叫回归测试（Regression Test）。

## 十七、Mock 与 Patch

如果测试每次都调用真实 DeepSeek，就会消耗额度、依赖网络，而且模型回答可能变化。因此测试使用 Mock 作为替身：

```text
正式运行：FastAPI → generate_debug_hint → DeepSeek
测试运行：FastAPI → generate_debug_hint 的替身 → 固定测试结果
```

`patch()` 会在测试期间临时替换函数，测试结束后再自动恢复。Mock 不是伪造产品功能，而是隔离外部依赖，让测试结果稳定、快速且可重复。

## 十八、从占位复盘到可填写表单

原来的“本次学习记录”只是占位文字。现在它包含四个受控输入框：

- 错误类型
- 涉及知识点
- 我的错误原因
- 下次如何避免

用户点击“我找到问题了”后，表单才会解锁。保存时使用 `some()` 和 `trim()` 检查四项是否完整，从而形成“先调试、再复盘”的产品流程。

## 十九、localStorage 与 JSON 序列化

`localStorage` 是浏览器提供的本地键值存储。BugMentor 使用固定键名保存学习记录：

```javascript
const STORAGE_KEY = "bugmentor-learning-records";
```

保存和读取链路是：

```text
复盘对象
→ JSON.stringify() 序列化
→ localStorage
→ JSON.parse() 反序列化
→ React 状态
→ 历史记录卡片
```

刷新页面或重新打开浏览器后，记录仍然存在。代码通过 `.slice(-20)` 只保留最近20条，避免数据无限增长。

当前记录只保存在当前浏览器，不会上传后端或 GitHub，也不能跨设备同步；清理浏览器网站数据后可能消失。这适合当前 MVP，未来若需要账号同步，则要使用后端数据库。

## 二十、历史列表、map 与数据验证

React 使用 `map()` 把记录数组转换成多个页面卡片：

```text
learningRecords
→ map(record)
→ 多个 record-card
→ 页面历史列表
```

`[...learningRecords].reverse()` 先复制数组再倒序，让最新记录显示在最上面，而不直接修改 React 状态中的原数组。

浏览器存储也属于外部数据。`isValidLearningRecord()` 会检查记录是否为对象、复盘字段是否为字符串、保存时间是否为合法日期，再通过 `filter()` 只保留有效记录。

React 使用 `{record.errorType}` 等形式将记录作为普通文字显示，没有使用 `innerHTML`，因此记录不会被当成网页代码执行。
