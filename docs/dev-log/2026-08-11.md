## 今日目标

## 今天完成了什么

### 1. 确定产品方向

调研了多个 AI 编程学习和 Debug 教练项目，对比了代码解释器、苏格拉底式教学工具、学习助手和编辑器插件。

最终确定产品方向：

> BugMentor——不会直接告诉你答案的 AI Debug 教练。

目标用户是正在学习 Python、能够编写简单程序，但缺乏独立 Debug 能力的大学生和编程初学者。

### 2. 确定 MVP

确定第一版产品的核心流程：

1. 用户提交代码、报错信息和预期结果
2. 系统分析问题
3. 系统通过逐级提示引导用户
4. 用户自己修改并解决问题
5. 完成后进行错误复盘

同时决定第一版只支持 Python，不做登录、社区、多语言和复杂课程系统。

## 今天学会了什么

### Git 与 GitHub

- 仓库是保存项目代码和历史记录的地方
- `clone` 是把云端仓库下载到电脑
- `commit` 是记录一个阶段的修改
- `push` 是把本地提交上传到 GitHub
- 网络推送失败不会导致本地代码丢失
- 一项完整的小功能适合形成一次独立提交

### Node.js、npm 与 Vite

- Node.js 提供前端开发所需的运行环境
- npm 用于安装和管理项目依赖
- Vite 可以快速创建和运行 React 项目
- 开发服务器可以在代码保存后自动更新网页
- `npm run build` 用于检查并生成正式网站文件

### React

- JSX 用来描述页面结构
- `useState` 可以保存网页状态
- `onClick` 用来响应按钮点击
- `onChange` 可以读取输入框内容
- 状态发生变化后，React 会自动更新页面
- 可以通过条件判断让页面根据用户操作显示不同内容

### CSS

- `grid` 可以实现左右两栏布局
- `padding` 和 `gap` 可以控制页面间距
- `border-radius` 可以设置圆角
- `:focus` 可以设置输入框的选中状态
- `@media` 可以让页面适应手机屏幕

### Debug 思路

今天遇到问题时，学会了先看报错信息，再区分：

- 是代码问题
- 是环境问题
- 是系统安全策略问题
- 还是网络连接问题

而不是看到报错后立刻重新安装或删除项目。
