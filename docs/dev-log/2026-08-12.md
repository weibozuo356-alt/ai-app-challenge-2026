## 二、重新理解前端技术栈

### 1. HTML：网页的结构与内容

HTML 用来描述网页中有什么，例如标题、段落、按钮、输入框和内容区域。可以把它理解为房子的结构，决定页面有哪些“房间”，但通常不负责装修和交互。

在 React 项目中，我主要通过 JSX 编写类似 HTML 的页面结构。JSX 不是新的编程语言，本质上仍然属于 JavaScript，需要由 Vite 处理后才能交给浏览器执行。

### 2. CSS：网页的外观与布局

CSS 控制颜色、字体、大小、间距、边框、排列方式和响应式布局。如果 HTML 是房子的结构，那么 CSS 就是装修。

BugMentor 的双栏布局、卡片、按钮颜色和输入框样式都由 `App.css` 控制。

### 3. JavaScript：网页的行为与逻辑

JavaScript 负责页面的交互和业务逻辑，例如：

- 响应按钮点击
- 读取用户输入
- 校验代码是否为空
- 向后端发送请求
- 根据请求结果修改页面内容

浏览器本身就能运行 JavaScript，不需要依赖 Node.js。Node.js 是让 JavaScript 在浏览器之外运行的另一种环境。

### 4. React：用组件和状态组织界面

React 是用于构建用户界面的 JavaScript 库。它最重要的两个概念是组件和状态。

组件可以把大页面拆成多个小模块；状态则是页面当前需要记住的数据。BugMentor 使用状态保存：

- 用户输入的代码
- 预期结果
- 报错信息
- 当前提示等级
- 是否正在请求后端
- 是否已经解决问题
- 教练当前显示的文字

当状态发生变化时，React 会重新渲染需要变化的页面内容。

### 5. Node.js、npm 和 Vite

Node.js 让 JavaScript 可以在浏览器之外运行。在 BugMentor 中，它主要负责运行 npm 和 Vite 等前端开发工具。

npm 是前端的软件包管理工具，负责安装 React、Vite 等依赖，记录依赖版本，并执行 `npm run dev`、`npm run build` 等命令。

Vite 提供前端开发服务器、代码热更新和正式构建功能。开发时它把前端运行在 `http://localhost:5173`；构建时则把源代码整理成可以部署的网页文件。

前端技术之间的关系可以概括为：

```text
网页
├── HTML / JSX：结构和内容
├── CSS：外观和布局
└── JavaScript：行为和逻辑
    └── React：用组件和状态管理复杂界面

Node.js：在浏览器之外运行前端开发工具
├── npm：安装和管理依赖
└── Vite：启动开发环境并完成构建
```

## 三、后端是什么

前端是用户能看见和操作的页面，后端则是隐藏在页面背后的处理中心。它负责接收数据、检查数据、执行处理逻辑，并把结果返回给前端。

可以把整个应用理解为餐厅：

```text
用户 = 顾客
前端页面 = 服务员和菜单
HTTP 请求 = 服务员传递订单
后端 = 厨房
后端响应 = 厨房完成订单并返回
页面更新 = 服务员把结果交给顾客
```

### 1. Python

Python 是今天后端使用的编程语言。前端使用 JavaScript，后端使用 Python，两种语言通过 HTTP 和 JSON 交换数据。

### 2. FastAPI

FastAPI 是 Python Web 后端框架。它帮助我创建接口、接收 HTTP 请求、读取 JSON、返回 JSON，并自动生成 `/docs` 测试页面。

下面的代码创建了后端应用：

```python
app = FastAPI()
```

下面的代码表示：收到发往 `/api/debug` 的 POST 请求时，执行 `debug_code()`：

```python
@app.post("/api/debug")
def debug_code(request: DebugRequest):
```

### 3. Uvicorn

FastAPI 用于编写后端逻辑，Uvicorn 则负责真正运行这个后端服务并监听请求。

终端显示：

```text
Uvicorn running on http://127.0.0.1:8000
```

说明后端正在监听本机的 `8000` 端口。

### 4. Python 虚拟环境、pip 和 requirements.txt

`backend/.venv` 是 BugMentor 后端专用的 Python 环境。它把当前项目需要的软件包与电脑上的其他 Python 项目隔离开，避免版本互相影响。

pip 是 Python 的软件包安装工具，负责安装 FastAPI 等依赖。

`backend/requirements.txt` 记录项目依赖。其他人下载项目后，可以根据它重新安装相同的软件包，而不需要上传整个 `.venv`。

它们的关系是：

```text
Python
├── venv：隔离项目环境
├── pip：安装软件包
└── requirements.txt：记录项目依赖
```

## 四、API、HTTP 和 JSON

### 1. API：前端访问后端的窗口

API 可以理解为后端提供的“办事窗口”。BugMentor 当前提供：

- `GET /`：检查后端是否运行
- `POST /api/debug`：提交调试信息并获取提示

### 2. HTTP：前后端通信规则

HTTP 是浏览器与服务器之间的通信规则。

- `GET` 通常用于获取内容
- `POST` 通常用于提交数据

成功请求通常返回状态码 `200`。地址不存在会返回 `404`，数据不符合要求时 FastAPI 通常返回 `422`，后端内部故障可能返回 `500`。

测试时出现过 `/favicon.ico 404`，只是浏览器请求网页图标而后端没有提供，不影响 API 功能。

### 3. JSON：不同语言之间的数据格式

React 前端将数据转换成 JSON：

```json
{
  "code": "print(1 / 0)",
  "expected_result": "输出一个数字",
  "error_message": "ZeroDivisionError: division by zero",
  "hint_level": 1
}
```

FastAPI 返回：

```json
{
  "hint_level": 1,
  "hint": "第一级提示：先查看报错信息的最后一行……",
  "mode": "mock"
}
```

因此 JavaScript 和 Python 虽然是不同语言，仍然可以通过 JSON 交换数据。

## 五、Pydantic 与输入校验

Pydantic 用于描述并校验后端接受的数据。`DebugRequest` 相当于为 `/api/debug` 制定了一张数据表格。

```python
code: str = Field(min_length=1, max_length=10000)
hint_level: int = Field(default=1, ge=1, le=5)
```

这些规则表示代码不能为空且不能超过 10000 个字符，提示等级必须是 1～5 的整数。

专业上，这叫输入校验（Input Validation）。后端不能直接相信用户提交的数据，所以必须在系统边界检查类型、长度和范围。

## 六、React 如何请求后端

### 1. 受控输入框

React 使用状态保存输入框内容：

```javascript
const [expectedResult, setExpectedResult] = useState("");
```

用户输入时触发 `onChange`，再通过 `setExpectedResult` 更新状态。这种由 React 状态控制的输入框叫作受控组件（Controlled Component）。

### 2. fetch

前端通过 `fetch` 向后端发送请求：

```javascript
fetch("http://127.0.0.1:8000/api/debug", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify(...),
});
```

`JSON.stringify()` 会把 JavaScript 对象转换为 JSON 文本。

### 3. async 和 await

网络请求需要时间，所以它属于异步操作（Asynchronous Operation）。

`async` 表示函数中存在异步操作，`await` 表示等待当前请求返回后再继续执行这个函数后面的代码。它只暂停当前函数，不会让整个网页停止响应。

### 4. try、catch 和 finally

- `try`：尝试发送请求并处理结果
- `catch`：请求失败时显示连接错误
- `finally`：无论成功或失败，都结束加载状态

### 5. Loading State 和条件渲染

`isLoading` 用来记录请求是否正在进行。请求期间按钮显示“正在分析……”，并暂时禁止重复点击。

根据状态选择显示不同内容，叫作条件渲染（Conditional Rendering）。

## 七、CORS 与 Origin

前端运行在：

```text
http://localhost:5173
```

后端运行在：

```text
http://127.0.0.1:8000
```

一个来源（Origin）由协议、主机和端口组成。只要其中一项不同，浏览器就认为它们来自不同来源。

CORS 的全称是跨源资源共享（Cross-Origin Resource Sharing）。后端通过 CORS 配置明确允许 `http://localhost:5173` 访问，浏览器才会放行前端请求。

## 八、今天跑通的完整数据链路

```text
1. 用户在 BugMentor 输入代码、预期结果和报错信息
2. React 通过状态保存输入
3. 用户点击“开始侦查 Bug”
4. fetch 将数据转换成 JSON 并发送 POST 请求
5. FastAPI 的 /api/debug 接口接收请求
6. Pydantic 检查字段类型、长度和提示等级
7. 后端根据 hint_level 选择对应的模拟提示
8. 后端以 JSON 返回 hint_level、hint 和 mode
9. React 使用 response.json() 读取结果
10. React 更新 coachMessage 和 hintLevel 状态
11. 页面自动重新渲染并显示新的提示
```

用一句话概括：

> 我使用 React 收集用户输入，通过 `fetch` 将 JSON 格式的调试信息发送到 FastAPI 的 `/api/debug` 接口；后端使用 Pydantic 校验数据，根据提示等级生成结果，再以 JSON 返回，React 收到结果后更新状态并重新渲染页面。

## 九、模拟提示与真实 AI 的关系

当前后端通过固定的 `hints` 字典返回内容，因此它还没有真正分析代码。响应中的 `mode: "mock"` 表示当前使用的是模拟实现。

但是今天的工作不是临时代码。真正接入 AI 后，前端提交数据、后端接收数据、返回 JSON 和页面更新的流程基本不需要重做，只需要把后端的固定提示逻辑替换成大模型调用：

```text
当前：React → FastAPI → 固定提示 → React
未来：React → FastAPI → 大模型 API → 个性化提示 → React
```

## 十、安全边界与 Git 管理

当前后端只把用户代码当作普通文本处理，不会直接运行它。这样可以避免用户提交的恶意代码在服务器上执行。

接口限制了代码和报错信息的长度，CORS 只允许本地前端来源访问。未来接入模型后，模型输出也只能当作文本展示，不能直接交给系统执行。

`.gitignore` 用来阻止不应该上传的文件进入 GitHub：

- `.venv`：体积大且可以重新创建
- `node_modules`：可以通过 npm 重新安装
- `dist`：可以重新构建
- `.env`：未来用于保存 API 密钥，绝不能上传

## 十一、今天遇到的问题与排错

### 1. 虚拟环境提示无法复制文件

虽然终端出现 `Unable to copy`，但检查后发现 `.venv` 中的 Python 和 pip 实际已经能够运行。问题来自重复创建已存在的虚拟环境，因此不需要删除项目，只需要验证环境是否可用并继续安装依赖。

### 2. 前端网址返回 502

后端正常，但当时没有 Vite/Node 前端进程。重新运行 `npm run dev` 后，`http://localhost:5173` 恢复正常。

这让我理解：前端和后端是两个独立服务，需要分别启动并各自占用一个终端。

### 3. JSX 结束符写错

输入框的 `/>` 一度被写成错误格式，导致 JSX 语法异常。修正后正式构建通过。之后使用 Prettier 统一了代码格式。

### 4. Git 忽略规则

提交前检查了 `.gitignore`，确认 `.venv`、`node_modules`、`dist` 和 `.env` 没有上传。最终本地 `main` 与 GitHub 的 `origin/main` 保持一致。

## 十三、今日理解纠正

1. JavaScript 不需要建立在 Node.js 上才能运行；浏览器本身就可以执行 JavaScript。
2. npm 不只是调用模板，而是负责安装、记录和管理前端依赖。
3. 后端不是“另一个页面”，而是接收请求、处理数据并返回结果的程序。
4. 点击按钮后页面不会自动产生报错；当前产品需要用户填写已有的报错信息，后端再根据这些信息提供提示。
5. 当前 BugMentor 已经有真实的前后端通信，但提示内容仍然是模拟规则，还不是真正的 AI 分析。
